# 02_Python逻辑判断

## 为什么要学习逻辑判断
### 为什么要学这个知识
先通俗说：如果程序不会“判断”，它就只能从上往下死板执行，像一个不会思考的机器。  
再术语说：逻辑判断是通过布尔表达式控制程序分支流程（Control Flow）的核心机制，是所有业务规则实现的基础。

术语卡片：
- 一句话定义：逻辑判断是根据条件真假决定代码是否执行或执行哪条路径。
- 通俗比喻：像地铁闸机，刷卡成功才放行，否则拦住。
- 反例：不写判断就直接扣款，可能在余额不足时仍然扣款，导致严重错误。

优点：
- 让程序具备“选择能力”。
- 能表达真实业务规则（登录、权限、优惠、风控等）。

缺点：
- 条件复杂时，代码容易嵌套过深、可读性下降。

适用场景：
- 权限验证、表单校验、价格规则、游戏逻辑、流程分支。

不适用场景：
- 完全线性、无分支的一次性脚本（极少见）。

最小可运行案例（5~15 行）：
```python
age = 20
if age >= 18:
    print("你已成年，可进入")
if age < 18:
    print("你未成年，禁止进入")
print("判断结束")
```

输入示例：
- 无（代码内固定值）

输出示例：
```text
你已成年，可进入
判断结束
```

检查点：
- 同一条件下只会命中符合的分支语句。

课堂提问（含答案）：
1. 问：逻辑判断和顺序执行最大的差别是什么？  
   答：顺序执行不做选择；逻辑判断会根据条件真假选择执行路径。
2. 问：为什么说逻辑判断是业务规则的核心？  
   答：业务规则本质是“满足条件才允许/才计算/才执行”。

练习题：
- 设计一个“体温是否正常”的判断：36.3~37.2 输出“正常”，否则输出“异常”。

### 风险提醒
- 刚入门最常见错误是“以为写了 if 就一定会执行”。

### 考试/面试易错点
- 说不清“条件表达式必须返回什么类型”（应为布尔结果）。

### 本节小结
- 是什么：基于条件真假控制程序路径。  
- 为什么：没有判断就无法表达真实业务规则。  
- 怎么用：先写条件表达式，再写对应分支代码。

## 布尔类型与比较运算符
### 为什么要学这个知识
先通俗说：判断题只有“对/错”两个答案，程序里就是 `True/False`。  
再术语说：布尔类型（bool）是逻辑系统最小值域，比较运算符用于生成布尔结果。

术语卡片：
- 一句话定义：布尔类型只有 `True` 和 `False` 两个值。
- 通俗比喻：像电灯开关，只有开/关两种状态。
- 反例：把 `"True"`（字符串）当成 `True`（布尔值）使用。

优点：
- 判断结果清晰、可组合。
- 是 if/while/逻辑运算的输入基础。

缺点：
- 初学者容易混淆“字符串真假词”和“布尔值”。

适用场景：
- 条件分支、状态标识、权限开关。

不适用场景：
- 存储复杂业务数据（应使用结构化类型）。

### 布尔值基础
先错后对：
- 错误写法：`flag = "True"`（这是字符串）
- 正确写法：`flag = True`
- 原因：只有不带引号的 `True/False` 才是布尔字面量。

最小可运行案例：
```python
v1 = True
v2 = False
print(v1, type(v1))
print(v2, type(v2))
```

输入示例：
- 无

输出示例：
```text
True <class 'bool'>
False <class 'bool'>
```

检查点：
- `type(True)` 必须是 `<class 'bool'>`。

课堂提问（含答案）：
1. 问：`"False"` 和 `False` 一样吗？  
   答：不一样，前者是字符串，后者是布尔值。
2. 问：为什么布尔值重要？  
   答：因为所有条件判断最终都要归约为 True/False。

练习题：
- 分别定义三个变量：布尔值、字符串 `"True"`、整数 `1`，打印类型并解释区别。

### 比较运算符
常见符号：`==` `!=` `>` `<` `>=` `<=`

先错后对：
- 错误写法：`if age = 18:`  
- 正确写法：`if age == 18:`  
- 原因：`=` 是赋值，`==` 才是比较。

最小可运行案例：
```python
a = 5
b = 5.0
print(a == b)
print(a != b)
print(a >= b)
print("12" > "5")
```

输入示例：
- 无

输出示例：
```text
True
False
True
False
```

检查点：
- 字符串比较按字符编码逐位比较，不是按“数字大小直觉”。

边界与限制：
- `int` 和 `str` 不能直接按大小比较（如 `5 > "3"` 会报错）。

课堂提问（含答案）：
1. 问：为什么 `5 == 5.0` 是 True？  
   答：数值相等，Python 会比较值而非显示形式。
2. 问：为什么 `"12" > "5"` 是 False？  
   答：字符串按字典序比较，先比首字符 `"1"` 与 `"5"`。

练习题：
- 写 6 条比较表达式，覆盖全部比较运算符并打印结果。

### 风险提醒
- 混淆 `=` 与 `==` 会直接导致语法或逻辑错误。

### 考试/面试易错点
- 不了解字符串比较规则（字典序）。

### 本节小结
- 是什么：布尔值 + 比较运算符共同组成条件判断基础。  
- 为什么：if 的条件必须产出布尔结果。  
- 怎么用：用比较运算符构造条件表达式，输出 True/False。

## 逻辑运算符（and / or / not）
### 为什么要学这个知识
先通俗说：单个条件不够时，要把多个条件“并且/或者/取反”组合起来。  
再术语说：逻辑运算符用于布尔表达式组合，构建复合条件（compound condition）。

术语卡片：
- 一句话定义：逻辑运算符是对布尔值进行组合或取反的运算符。
- 通俗比喻：门禁规则里“刷卡且人脸通过”就是 and；“手机号或邮箱登录”就是 or。
- 反例：把 and/or 当成自然语言理解，不看优先级。

优点：
- 表达复杂规则更紧凑。
- 能减少多层 if 的冗余判断。

缺点：
- 条件过长会显著降低可读性。

适用场景：
- 权限校验、组合筛选、业务规则引擎。

不适用场景：
- 单一条件场景（直接比较更清晰）。

### and / or / not 用法
先错后对：
- 错误写法：`if age > 18 or age < 30:`（本意是区间内，却写成并集）
- 正确写法：`if age > 18 and age < 30:`
- 原因：区间内要“同时满足”上下界。

最小可运行案例：
```python
age = 19
print(age > 5 and age < 18)
print(age > 5 or age < 18)
print(not age > 18)
```

输入示例：
- 无

输出示例：
```text
False
True
False
```

检查点：
- `not` 只做取反，不改变原变量值。

边界与限制：
- 复合条件建议加括号，避免阅读歧义。

课堂提问（含答案）：
1. 问：判断“18 到 30 岁之间”为什么不能用 or？  
   答：or 会放宽条件，几乎总为 True；区间应使用 and。
2. 问：`not (age > 18)` 和 `age <= 18` 总是等价吗？  
   答：在纯数值比较场景等价。

练习题：
- 写一个“可进入会员区”的条件：余额大于 1000 且会员等级 >= 3。

### 风险提醒
- 复合条件越长越容易出错，建议拆分中间变量。

### 考试/面试易错点
- and/or 的优先级和语义误用。

### 本节小结
- 是什么：布尔表达式的组合工具。  
- 为什么：现实规则几乎都由多个条件组成。  
- 怎么用：先写单条件，再用 and/or/not 组合。

## if 单分支判断
### 为什么要学这个知识
先通俗说：满足条件才执行，不满足就跳过。  
再术语说：if 单分支是最基础的条件执行结构（conditional single-branch execution）。

术语卡片：
- 一句话定义：if 语句在条件为 True 时执行缩进代码块。
- 通俗比喻：门票检查“成年才放行”。
- 反例：把 if 内代码和外部代码缩进写错，导致逻辑失效。

优点：
- 结构简单，适合基础规则。

缺点：
- 不能覆盖条件不成立时的处理逻辑。

适用场景：
- 条件触发式提醒、日志打印、简单权限放行。

不适用场景：
- 需要“否则”路径的业务。

### if 语法与缩进
先错后对：
- 错误写法：`if age >= 18`（缺少冒号）
- 正确写法：`if age >= 18:`
- 原因：冒号用于引出代码块。

最小可运行案例：
```python
age = int(input("请输入年龄: "))
if age >= 18:
    print("你已成年")
print("流程结束")
```

输入示例：
- `20`

输出示例：
```text
请输入年龄: 20
你已成年
流程结束
```

检查点：
- 当输入 `17` 时不会打印“你已成年”。

边界与限制：
- 条件表达式必须可求出布尔结果。

课堂提问（含答案）：
1. 问：if 条件不成立时，程序会报错吗？  
   答：不会，只是跳过 if 代码块。
2. 问：为什么 Python 要求缩进？  
   答：缩进定义代码块归属，是语法的一部分。

练习题：
- 输入身高，若大于 180 输出“可报名篮球队”。

### 风险提醒
- 初学者常把 if 内外代码缩进写乱。

### 考试/面试易错点
- 条件表达式写成赋值表达式。

### 本节小结
- 是什么：满足条件才执行的单分支结构。  
- 为什么：最小成本实现“有条件动作”。  
- 怎么用：`if 条件:` + 缩进代码块。

## if-else 双分支判断
### 为什么要学这个知识
先通俗说：条件成立做 A，不成立做 B。  
再术语说：if-else 是二选一控制结构（binary branch），保证两条路径必走其一。

术语卡片：
- 一句话定义：if-else 在条件真时执行 if 块，否则执行 else 块。
- 通俗比喻：考试及格发证书，否则补考。
- 反例：在需要兜底逻辑时仍只写 if，导致“不满足时什么都不做”。

优点：
- 覆盖完整，逻辑闭环。

缺点：
- 只能处理二分决策。

适用场景：
- 是否通过、是否收费、是否触发告警。

不适用场景：
- 三种及以上互斥分支（更适合 if-elif-else）。

### if-else 实战
最小可运行案例：
```python
money = int(input("请输入余额: "))
if money >= 10000:
    print("可以买新电脑")
else:
    print("先攒钱")
print("判断完成")
```

输入示例：
- `9000`

输出示例：
```text
请输入余额: 9000
先攒钱
判断完成
```

检查点：
- 同一次判断只能进入 if 或 else 其中一个分支。

先错后对：
- 错误写法：`else money < 10000:`  
- 正确写法：`else:`  
- 原因：else 不写条件，表示“其他所有情况”。

课堂提问（含答案）：
1. 问：什么时候必须用 else？  
   答：当你希望“不满足条件时也必须执行某逻辑”。
2. 问：if 和 else 会同时执行吗？  
   答：不会，二选一。

练习题：
- 输入身高，超过 120 输出“收费 10 元”，否则“免费”。

### 风险提醒
- else 与 if 的缩进层级必须对齐。

### 考试/面试易错点
- 在 else 后误写条件。

### 本节小结
- 是什么：条件二选一结构。  
- 为什么：保证“满足/不满足”都有处理结果。  
- 怎么用：`if 条件:` ... `else:` ...

## if-elif-else 多分支判断
### 为什么要学这个知识
先通俗说：不止两种情况时，需要“多选一”。  
再术语说：if-elif-else 用于互斥条件链（mutually exclusive chain），按顺序匹配首个为 True 的分支。

术语卡片：
- 一句话定义：多个条件按顺序判断，命中一个即停止后续判断。
- 通俗比喻：景区优惠规则：先看身高，再看 VIP，再看日期。
- 反例：把多个 if 并列写，导致多分支同时命中。

优点：
- 结构清晰，适合多条件互斥决策。

缺点：
- 条件链太长时维护成本高。

适用场景：
- 成绩评级、优惠等级、风控规则分级。

不适用场景：
- 多条件可以同时生效（应使用多个独立 if）。

### 多分支示例
最小可运行案例：
```python
height = int(input("请输入身高: "))
vip = int(input("请输入VIP等级: "))
day = int(input("今天几号: "))
if height < 120:
    print("免费(身高)")
elif vip > 3:
    print("免费(VIP)")
elif day == 1:
    print("免费(1号活动)")
else:
    print("收费10元")
```

输入示例：
- `130`, `4`, `10`

输出示例：
```text
请输入身高: 130
请输入VIP等级: 4
今天几号: 10
免费(VIP)
```

检查点：
- 命中 `vip > 3` 后，不会继续检查 `day == 1`。

先错后对：
- 错误写法：把互斥规则写成多个并列 if。  
- 正确写法：使用 if-elif-else 链。  
- 原因：互斥规则应只命中一个分支。

课堂提问（含答案）：
1. 问：elif 和 if 的区别是什么？  
   答：elif 依赖前面分支未命中才会判断；独立 if 不依赖。
2. 问：为什么多分支要注意“顺序”？  
   答：先命中先退出，顺序会直接影响结果。

练习题：
- 输入分数，输出等级：90+ A，80+ B，60+ C，其他 D。

### 风险提醒
- 条件顺序设计不当会“抢命中”。

### 考试/面试易错点
- 不清楚 elif 的短路特性。

### 本节小结
- 是什么：按顺序匹配的多分支结构。  
- 为什么：处理多种互斥业务状态。  
- 怎么用：先写最优先规则，再写次优先规则，最后 else 兜底。

## if 嵌套判断
### 为什么要学这个知识
先通俗说：有些规则是“先过第一关，再看第二关”。  
再术语说：if 嵌套是分层条件决策模型（hierarchical conditional model），用于表达前置条件与后置条件依赖关系。

术语卡片：
- 一句话定义：在一个 if 分支中继续使用 if，形成多层判断。
- 通俗比喻：先验身份证，再验会员卡。
- 反例：把有依赖关系的条件硬并列，逻辑混乱且难维护。

优点：
- 能清晰表达“前置门槛 + 次级规则”。

缺点：
- 层级过深时可读性变差。

适用场景：
- 权限校验、审批流、多阶段资格判断。

不适用场景：
- 简单并列条件（应先考虑逻辑运算或多分支）。

### 嵌套示例
最小可运行案例：
```python
height = int(input("请输入身高: "))
if height > 120:
    vip = int(input("请输入VIP等级: "))
    if vip > 3:
        print("VIP免费")
    else:
        print("收费10元")
else:
    print("身高免票")
```

输入示例：
- `130`, `2`

输出示例：
```text
请输入身高: 130
请输入VIP等级: 2
收费10元
```

检查点：
- 只有第一层条件满足，才会进入第二层输入与判断。

先错后对：
- 错误写法：第二层判断缩进错位。  
- 正确写法：内层 if 必须在外层代码块缩进内。  
- 原因：缩进即层级关系。

课堂提问（含答案）：
1. 问：什么时候该用嵌套而不是 and？  
   答：当后续判断依赖前置判断结果，且分层含义明显时。
2. 问：嵌套过深怎么办？  
   答：可拆函数、引入提前返回、合并条件提升可读性。

练习题：
- 编写“发礼物资格判断”：18~30 岁，且（工龄>=2 或级别>3）。

### 风险提醒
- 过深嵌套会让代码像“楼梯迷宫”。

### 考试/面试易错点
- 缩进错一个层级，逻辑完全改变。

### 本节小结
- 是什么：条件中的条件，形成层级决策。  
- 为什么：表达前置门槛与后置规则。  
- 怎么用：先外层筛选，再内层细分。

## 逻辑判断综合实战
### 为什么要学这个知识
先通俗说：会单点不算会，能做完整小程序才算掌握。  
再术语说：综合实战用于验证你能否把比较、逻辑、分支、输入组合成完整业务流。

术语卡片：
- 一句话定义：综合实战是多知识点协同应用的能力验证。
- 通俗比喻：零件都认识了，现在要组装整机。
- 反例：只会写单个 if，遇到真实业务就不会拆规则。

优点：
- 提升迁移能力和排错能力。

缺点：
- 基础不牢时容易出现连锁错误。

适用场景：
- 面试手写题、课堂结课项目、业务规则脚本。

不适用场景：
- 仅做概念记忆、不需要动手实践的场景。

### 实战 1：猜数字三次机会
最小可运行案例：
```python
import random
target = random.randint(1, 10)
for i in range(1, 4):
    guess = int(input(f"第{i}次猜数字(1-10): "))
    if guess == target:
        print("猜中了")
        break
    elif guess > target:
        print("猜大了")
    else:
        print("猜小了")
```

输入示例：
- `8`, `5`, `3`

输出示例：
- 依据随机数不同，出现“猜大了/猜小了/猜中了”。

检查点：
- 能给出方向性提示，而不仅是“对/错”。

练习题：
- 在最后补充“游戏结束，正确答案是 X”。

### 5 个必会报错（含原因与修复）
1. `SyntaxError: invalid syntax`  
   原因：常见于 if 后漏冒号。  
   修复：补 `:`。  
2. `IndentationError`  
   原因：缩进错位或混用空格/Tab。  
   修复：统一 4 空格缩进。  
3. `ValueError: invalid literal for int()`  
   原因：`int()` 转换了非数字字符串。  
   修复：先校验输入，再转换。  
4. `TypeError`（比较或运算类型不兼容）  
   原因：如 `5 > "3"`。  
   修复：统一类型后比较。  
5. 逻辑正确但结果不符合预期  
   原因：and/or 用错或分支顺序不当。  
   修复：打印中间条件值逐步排查。
