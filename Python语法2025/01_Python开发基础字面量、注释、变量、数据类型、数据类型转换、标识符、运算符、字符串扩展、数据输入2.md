### 考试/面试易错点

### 本节小结

## 字面量
### 为什么要学这个知识
先通俗说：字面量就是你在代码里“直接写死”的值。  
再术语说：字面量（literal）是源代码中表示固定值的语法形式，是表达式求值的基础输入。

优点：
- 写法直接，表达清晰。
- 是所有表达式的最小组成单位。

缺点：
- 过度依赖字面量会导致“硬编码”问题。

适用场景：
- 常量值展示、演示样例、初始化变量。

不适用场景：
- 频繁变化的数据（应该放变量或配置）。

### 字面量类型与写法
常见字面量：
- 整数：`666`
- 浮点数：`13.14`
- 字符串：`"人生苦短，我用Python"`
- 布尔：`True`、`False`

```python
print(666)
print(13.14)
print("人生苦短，我用Python")
print(True)
```

可验证结果：

```text
666
13.14
人生苦短，我用Python
True
```

检查点：
- 字符串必须加引号。
- 布尔首字母大写。

练习题：
- 分别写出一个整数、浮点数、字符串、布尔字面量并输出。

### 字面量与变量的关系
字面量负责“提供初始值”，变量负责“存储并复用值”。

```python
age = 18      # 18 是字面量
name = "张三" # "张三" 是字面量
print(age, name)
```

可验证结果：

```text
18 张三
```

练习题：
- 定义 3 个变量（姓名/年龄/城市），并标注每个变量右侧字面量类型。

### 风险提醒
- 中文全角引号、全角逗号会导致语法错误。

### 考试/面试易错点
- 误把变量名当字符串（`name` 与 `"name"` 混淆）。

### 本节小结
- 字面量是值的“原始写法”，变量是值的“可复用载体”。

## 注释
### 为什么要学这个知识
先通俗说：注释是写给“人”看的，不是写给“机器”看的。  
再术语说：注释（comment）是源代码中的非执行文本，用于说明意图、约束和上下文。

优点：
- 提升可读性和可维护性。
- 降低团队协作沟通成本。

缺点：
- 注释写得不准会误导阅读者。

适用场景：
- 解释复杂逻辑、边界条件、业务背景。

不适用场景：
- 用注释掩盖烂命名或烂结构。

### 单行注释和多行说明
```python
# 这是单行注释
"""
这是多行说明
用于解释一段代码的意图
"""
print("注释不会被执行")
```

可验证结果：

```text
注释不会被执行
```

检查点：
- 注释文本不会出现在运行输出里。

练习题：
- 给一段 5 行代码加上“做什么 + 为什么”的注释。

### 注释质量规范
- 注释“为什么”，不要重复“做了什么”。
- 与代码同步更新，避免过期注释。

可验证结果（检查点）：
- 让同学只看注释，能说出代码目的。

练习题：
- 把“无意义注释”改写为“有价值注释”3 条。

### 风险提醒
- 把注释当“文档垃圾桶”，导致噪音信息过多。

### 考试/面试易错点
- 把三引号字符串完全等同注释语法（它本质上是字符串）。

### 本节小结
- 好注释是“意图说明”，不是“代码复读机”。

## 变量
### 为什么要学这个知识
先通俗说：变量就是“有名字的盒子”，你把数据放进去，后面随时拿。  
再术语说：变量是符号名到对象引用的绑定机制，是程序状态管理的核心。

优点：
- 避免重复写值，提升可维护性。
- 让代码更有语义（读得懂）。

缺点：
- 命名不规范会让代码可读性变差。

适用场景：
- 任何需要复用或变更的数据。

不适用场景：
- 一次性且无复用价值的极短表达式。

### 变量定义与重赋值
```python
money = 50
name = "周杰伦"
print(money, name)

money = 10
name = "林俊杰"
print(money, name)
```

可验证结果：

```text
50 周杰伦
10 林俊杰
```

检查点：
- 第二次赋值覆盖第一次值。

练习题：
- 模拟“钱包余额变化”流程：初始 100，花费 35，充值 20，输出每一步。

### 变量复用价值
```python
name = "刘德华"
print(name)
print(name)
print(name)
```

可验证结果：

```text
刘德华
刘德华
刘德华
```

练习题：
- 写一段“班级介绍”，复用同一变量至少 5 次。

### 变量与表达式
```python
money = 50
print("初始余额：", money)
money = money - 10 - 5
print("最终余额：", money)
```

可验证结果：

```text
初始余额： 50
最终余额： 35
```

练习题：
- 用变量完成“购买商品后余额更新”并输出。

### 风险提醒
- 变量名过于随意（如 `a1`、`bbb`）会增加后期维护成本。

### 考试/面试易错点
- 混淆“变量名”和“变量值”。

### 本节小结
- 变量让程序从“写死值”升级到“可变状态”。

## 数据类型
### 为什么要学这个知识
先通俗说：不同类型的数据，能做的操作不同。  
再术语说：数据类型决定对象的语义、可用运算和内存表示。

优点：
- 能提前判断可用操作，减少运行时错误。
- 让代码逻辑更严谨。

缺点：
- 初学阶段要多记几种类型及其行为差异。

适用场景：
- 任何需要计算、比较、格式化、输入处理的代码。

不适用场景：
- 无（这是编程基础能力）。

### type() 查看类型
```python
print(type(666))
print(type(12.345))
print(type("python666"))

age = 11
height = 172.55
print(type(age))
print(type(height))
```

可验证结果（核心）：

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'int'>
<class 'float'>
```

练习题：
- 自定义 4 个变量并打印各自 `type()`。

### “变量有类型吗”这个常见问题
结论：更准确说法是“变量当前绑定的数据有类型”。

可验证结果（检查点）：
- 同一个变量可先绑定 `int` 再绑定 `str`，类型会变化。

练习题：
- 让同一变量先后存 `10`、`"10"`，每次都打印 `type()`。

### 风险提醒
- 看到 `<class 'str'>` 还当作数字去运算。

### 考试/面试易错点
- 不会解释动态类型语言中的变量绑定机制。

### 本节小结
- 类型是“数据行为说明书”，不会看类型就会频繁踩坑。

## 数据类型转换
### 为什么要学这个知识
先通俗说：你拿到的数据，常常不是你想要的类型。  
再术语说：类型转换（type casting）是将对象从一种表示转换为另一种表示的过程，是 I/O 与计算衔接的关键步骤。

优点：
- 打通输入与计算流程。
- 降低类型不匹配导致的异常。

缺点：
- 转换失败会抛出异常，需要错误处理意识。

适用场景：
- 用户输入、文件读取、接口返回值处理。

不适用场景：
- 已经是目标类型且无需转换。

### 常见转换函数
```python
t1 = str(123)
t2 = float(123)
t3 = int("123")
t4 = float("123.65")
print(type(t1), type(t2), type(t3), type(t4))
```

可验证结果：

```text
<class 'str'> <class 'float'> <class 'int'> <class 'float'>
```

练习题：
- 把 `"250"` 转成整数后加 `75` 输出结果。

### 转换失败场景
```python
# print(int("haha123"))
# print(float("haha123"))
```

可验证现象：
- 取消注释会报 `ValueError`。

练习题：
- 分别触发一次 `ValueError`，并用一句话写出错误原因。

### 真实项目场景案例
场景 1：表单年龄字段（前端传字符串）
```python
raw_age = "21"  # 来自表单
age = int(raw_age)
print(age + 1)
```

场景 2：CSV 读取后的数字计算
```python
price_text = "19.90"  # 来自CSV
price = float(price_text)
print(price * 3)
```

场景 3：日志中的数字字段解析
```python
latency_text = "120"
latency_ms = int(latency_text)
print(f"延迟: {latency_ms}ms")
```

可验证结果（检查点）：
- 未转换时会拼接字符串，转换后才能做数值运算。

练习题：
- 设计一个“订单数量字符串 -> 整数 -> 总价”小示例。

### 风险提醒
- `int(12.9)` 是截断，不是四舍五入。

### 考试/面试易错点
- 说不清 `str()`、`int()`、`float()` 的失败边界。

### 本节小结
- 转换能力决定你能不能写出稳定的输入处理代码。

## 标识符
### 为什么要学这个知识
先通俗说：命名混乱，代码再短也会看不懂。  
再术语说：标识符（identifier）是程序实体命名规则集合，直接影响可读性、可维护性与语法合法性。

优点：
- 好命名降低认知负担。
- 规范命名能减少低级语法错误。

缺点：
- 初期需要刻意训练命名习惯。

适用场景：
- 变量、函数、类、模块等所有命名行为。

不适用场景：
- 无。

### 命名规则
- 允许字母、数字、下划线（建议英文+下划线）。
- 不能数字开头。
- 大小写敏感。
- 不能用关键字。

```python
user_name = "alice"
age1 = 18
Age1 = 20
print(user_name, age1, Age1)
```

可验证结果：
- `age1` 与 `Age1` 是不同变量。

练习题：
- 写 6 个合法变量名和 4 个非法变量名，并说明原因。

### 关键字冲突示例
```python
# True = 1  # 会报错
```

可验证现象：
- 取消注释会触发 `SyntaxError`。

练习题：
- 列出 5 个你知道的 Python 关键字，并解释为什么不能用作变量名。

### 风险提醒
- 命名过短或无语义会让后续排错非常痛苦。

### 考试/面试易错点
- 不清楚大小写敏感导致同名误判。

### 本节小结
- 标识符规则是“语法合法 + 可维护性”双重底线。

## 运算符
### 为什么要学这个知识
先通俗说：程序要处理数据，运算符就是“算数据的工具”。  
再术语说：运算符定义了对象间的代数、逻辑或位级操作语义，是表达式计算核心。

优点：
- 能用少量代码表达复杂计算。
- 与变量结合后可构建业务公式。

缺点：
- 优先级和整除/除法差异容易出错。

适用场景：
- 金额、统计、计数、索引、公式计算。

不适用场景：
- 无（基础运算无处不在）。

### 算术运算符演示
```python
a = 7
b = 3
print(a + b)
print(a - b)
print(a * b)
print(a / b)
print(a // b)
print(a % b)
print(a ** b)
```

可验证结果：

```text
10
4
21
2.3333333333333335
2
1
343
```

练习题：
- 用 `//` 和 `%` 判断 `29` 分钟能分成多少组 5 分钟并余多少分钟。

### 优先级与可读性
- 复杂表达式建议加括号，避免阅读歧义。

```python
print(2 + 3 * 4)      # 14
print((2 + 3) * 4)    # 20
```

可验证结果：两行输出不同。

练习题：
- 写 3 个带括号与不带括号结果不同的表达式。

### 风险提醒
- `/` 一般返回浮点数，`//` 才是整除。

### 考试/面试易错点
- `%` 在字符串格式化和求余两种场景中混淆。

### 本节小结
- 运算符不难，难在“场景判断 + 细节边界”。

## 字符串扩展
### 为什么要学这个知识
先通俗说：程序不只是算对，还要“说清楚”。  
再术语说：字符串格式化是将结构化数据转换为可读文本的关键机制，影响日志、报表、提示信息质量。

优点：
- 提升输出可读性和表达效率。
- 适配日志、提示、报表等高频场景。

缺点：
- 方式多，初学容易混用或误用。

适用场景：
- 所有面向人的输出信息。

不适用场景：
- 仅内部临时调试且无展示需求的超短脚本。

### 三种字符串写法
- 单引号、双引号、三引号。

```python
a = 'hello'
b = "python"
c = """multi line"""
print(a, b, c)
```

可验证结果：三者类型均为 `str`。

练习题：
- 用三引号写一段 3 行的自我介绍并输出。

### 加号拼接
```python
name = "张三"
age = 11
info = "我是" + name + "，今年" + str(age) + "岁"
print(info)
```

可验证结果：

```text
我是张三，今年11岁
```

练习题：
- 用 `+` 拼接输出“姓名、班级、目标”。

### `%` 占位格式化
```python
name = "张三"
age = 11
height = 172.55
print("我是%s，今年%d岁，身高%.2fcm" % (name, age, height))
```

可验证结果：

```text
我是张三，今年11岁，身高172.55cm
```

练习题：
- 用 `%d`、`%f` 输出一条“库存数量和价格”信息。

### f-string 格式化
```python
name = "张三"
salary = 18000.55
print(f"我是{name}，工资{salary:.1f}")
print(f"两年后工资估算：{salary * 1.1 * 1.1:.2f}")
```

可验证结果（检查点）：
- 支持表达式，写法更直观。

练习题：
- 用 f-string 输出“当前余额 + 发薪后余额”，保留两位小数。

### 三种方式对比表
| 方式 | 可读性 | 性能（一般场景） | 兼容性 | 推荐度 |
| --- | --- | --- | --- | --- |
| `+` 拼接 | 中（变量多时差） | 中 | 高 | 中 |
| `%` 格式化 | 中 | 中 | 很高（老代码常见） | 中 |
| `f-string` | 高 | 高 | Python 3.6+ | 高（优先推荐） |

可验证结果（检查点）：
- 变量越多时，`f-string` 的可读性优势越明显。

练习题：
- 同一段业务文案分别用 `+`、`%`、`f-string` 写 3 版并对比可读性。

### 真实项目场景案例
场景 1：日志输出
```python
user_id = 1024
cost_ms = 83.6
print(f"[INFO] user={user_id} cost={cost_ms:.1f}ms")
```

场景 2：报表文案
```python
name = "华东一区"
rate = 0.8732
print(f"{name} 本周达成率：{rate:.2%}")
```

场景 3：支付提示
```python
amount = 128.5
print("应付金额：%.2f 元" % amount)
```

可验证结果：输出格式统一、可读、可复制进业务系统。

练习题：
- 设计一条“下单成功”提示，包含订单号、金额、收货人。

### 风险提醒
- 字符串与数字直接 `+` 会报 `TypeError`。

### 考试/面试易错点
- `%f` 默认 6 位小数，经常答错。

### 本节小结
- 字符串扩展的核心是“让结果可读、可维护、可复用”。

## 数据输入（input）
### 为什么要学这个知识
先通俗说：没有输入，程序就是“自说自话”；有了输入，程序才会“互动”。  
再术语说：`input()` 是标准输入接口（STDIN）的高级封装，是命令行交互程序的基础 I/O 能力。

优点：
- 快速构建交互式程序。
- 与类型转换组合后可覆盖大量入门业务场景。

缺点：
- 输入内容不可控，需要校验与异常处理意识。

适用场景：
- 命令行交互、小工具脚本、教学练习。

不适用场景：
- 复杂 GUI 或高并发 Web 输入（需专门框架层处理）。

### input 基础行为
```python
value = input("请输入内容：")
print(value, type(value))
```

可验证结果：
- 任意输入类型最终都是 `str`。

练习题：
- 输入你的名字并输出“你好，xxx”。

### 输入后转换再计算
```python
age = int(input("请输入年龄："))
print("10年后年龄：", age + 10)
```

可验证结果：
- 输入 `18`，输出 `28`。

练习题：
- 输入两门成绩（浮点数）并输出平均分（保留 2 位小数）。

```python
username = input("用户名：")
```

缺点：

不适用场景：
- 仅停留在语法片段记忆阶段。

### 股价小程序（综合）
```python
name = "程序员平安"
stock_price = 6.5
stock_code = "003032"
stock_price_daily_growth_factor = 1.2
growth_days = 7

print(f"公司：{name}，股票代码：{stock_code}，当前股价：{stock_price}")
print(
    "每日增长系数：%.1f，经过%d天增长后，股价达到：%.2f"
```
