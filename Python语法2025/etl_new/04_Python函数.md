# 04_Python函数

## 本章学习目标
- 理解函数是什么，为什么函数是“可维护代码”的起点。
- 掌握函数定义、调用、参数、返回值、作用域与递归入门。
- 能写出可运行、可验证、可排错的函数代码。
- 能把函数应用到真实小场景：成绩分析、用户信息格式化、数据清洗。

## 函数介绍：为什么要学函数
### 为什么要学这个知识
先通俗说：函数就是“提前写好的可重复动作包”。你把一个动作打包好，以后需要时直接调用，不用每次从头写。
再术语说：函数（Function）是可复用的代码块，用于封装特定逻辑，降低重复代码，提高抽象层次与可维护性。

术语卡片：
- 一句话定义：函数是带名字、可调用、可复用的程序逻辑单元。
- 通俗比喻：像厨房里的“配方卡片”，每次按卡片步骤做菜，质量稳定。
- 反例：把同样的打印/计算逻辑复制 10 次，后期改一处漏九处。

优点：
- 降低重复代码。
- 提高可读性和协作效率。
- 便于测试和排错。

缺点：
- 过度拆分会让代码跳转频繁。
- 命名不清晰会增加理解成本。

适用场景：
- 同一逻辑在多个地方重复出现。
- 一个问题可以被拆成多个步骤。

不适用场景：
- 一次性极短逻辑（1~2 行）且不会复用。

生活类比：
- 函数像“洗衣机程序”：你不需要每次手搓，按下按钮即可复用流程。

### 函数的价值：从“能跑”到“可维护”
最小可运行案例：
```python
def say_hello():
    print("你好，Python")

say_hello()
say_hello()
```

输入示例：
- 无

输出示例：
```text
你好，Python
你好，Python
```

检查点：
- 必须看到同一函数可被重复调用。
- 修改函数体后，所有调用点效果同步变化。

先错后对：
- 错误写法：复制粘贴两段完全一样的打印代码。
- 正确写法：写一个函数并调用两次。
- 原因：重复代码会导致维护灾难。

边界与限制：
- 函数不是越多越好，拆分要有意义。

课堂提问（含答案）：
1. 问：函数最核心解决什么问题？
   答：复用和维护问题。
2. 问：为什么“能跑”不等于“好代码”？
   答：能跑只说明当前可用，不代表未来可维护。

练习题：
- 题目：定义 `study_tip()` 输出“每天练习30分钟Python”。调用 3 次。
- 解题思路：先定义函数，再重复调用。
- 参考答案：
```python
def study_tip():
    print("每天练习30分钟Python")

study_tip()
study_tip()
study_tip()
```

### 风险提醒
- 别把函数写成“全局大杂烩”，函数应单一职责。

### 考试/面试易错点
- 只能背语法 `def`，说不出拆函数的标准。

### 本节小结（3行记忆框架）
- 是什么：可复用的逻辑单元。
- 为什么：减少重复并提升维护性。
- 怎么用：先抽动作，再命名函数，再调用验证。

## 函数基础语法：定义与调用
### 为什么要学这个知识
先通俗说：你得先会“造函数”和“用函数”，后面参数和返回值才有意义。
再术语说：函数定义（define）声明逻辑，函数调用（call）触发执行；二者是函数机制的基本闭环。

术语卡片：
- 一句话定义：定义负责“创建”，调用负责“执行”。
- 通俗比喻：定义像录菜谱，调用像照菜谱做菜。
- 反例：只定义不调用，程序不会自动执行函数体。

优点：
- 程序结构清晰。
- 逻辑与执行分离。

缺点：
- 新手常忽略调用，误以为“写了就会跑”。

适用场景：
- 所有函数化编程场景。

不适用场景：
- 无

### 定义语法与调用顺序
最小可运行案例：
```python
def print_line():
    print("-" * 20)

print("开始")
print_line()
print("结束")
```

输入示例：
- 无

输出示例：
```text
开始
--------------------
结束
```

检查点：
- `def` 只创建函数，不输出内容。
- 只有调用 `print_line()` 才会打印横线。

先错后对：
- 错误写法：
```python
print_line()
def print_line():
    print("-")
```
- 正确写法：先定义，再调用。
- 原因：解释器顺序执行，调用时函数尚未定义会报 `NameError`。

边界与限制：
- 函数名必须是合法标识符，不能用关键字。

课堂提问（含答案）：
1. 问：`def` 执行时会不会运行函数体？
   答：不会，只是创建函数对象。
2. 问：函数调用失败常见原因？
   答：调用早于定义、函数名拼写错误。

练习题：
- 题目：定义 `show_title()` 输出“学生管理系统”，并在程序中调用一次。
- 解题思路：遵循“先定义后调用”。
- 参考答案：
```python
def show_title():
    print("学生管理系统")

show_title()
```

### 风险提醒
- 缩进错误会让函数体不属于函数。

### 考试/面试易错点
- 认为函数“只能定义在文件开头”。

### 本节小结（3行记忆框架）
- 是什么：定义与调用的执行机制。
- 为什么：建立函数化编程基本功。
- 怎么用：先定义、后调用、看输出验证。

## 参数函数：让函数具备“可变输入能力”
### 为什么要学这个知识
先通俗说：没有参数的函数像固定按钮，有参数的函数像可调旋钮，更灵活。
再术语说：参数（parameter）是函数输入接口，实参（argument）是调用时传入的具体值。

术语卡片：
- 一句话定义：参数是函数接收外部数据的通道。
- 通俗比喻：像点奶茶选甜度，甜度就是参数。
- 反例：函数里写死姓名，导致只能服务一个人。

优点：
- 一套逻辑服务多份数据。
- 提升函数复用率。

缺点：
- 参数过多会降低可读性。

适用场景：
- 模板化输出、计算公式、数据处理。

不适用场景：
- 完全固定逻辑且永不变化。

### 形参与实参
最小可运行案例：
```python
def welcome(name, city):
    print(f"你好，{name}，欢迎来到{city}")

welcome("小王", "上海")
welcome("小李", "杭州")
```

输入示例：
- `("小王", "上海")`

输出示例：
```text
你好，小王，欢迎来到上海
你好，小李，欢迎来到杭州
```

检查点：
- 不同实参触发不同输出。
- 参数顺序对应正确。

先错后对：
- 错误写法：`welcome("上海", "小王")`
- 正确写法：顺序与形参一致，或用关键字参数。
- 原因：位置参数按顺序绑定。

边界与限制：
- 传参个数必须匹配（除默认参数和可变参数场景）。

课堂提问（含答案）：
1. 问：形参与实参有什么区别？
   答：形参是定义占位，实参是调用时具体值。
2. 问：参数顺序错了会怎样？
   答：通常不报错但语义错误，输出不符合预期。

练习题：
- 题目：写 `calc_bmi(weight, height)` 输出 BMI（保留2位）。
- 解题思路：BMI=体重/身高平方。
- 参考答案：
```python
def calc_bmi(weight, height):
    bmi = weight / (height ** 2)
    print(f"BMI={bmi:.2f}")

calc_bmi(60, 1.68)
```

### 风险提醒
- 参数语义不清会导致“代码能跑但业务错”。

### 考试/面试易错点
- 说不清位置参数和关键字参数区别。

### 本节小结（3行记忆框架）
- 是什么：函数输入接口。
- 为什么：让函数从固定逻辑变成通用逻辑。
- 怎么用：定义形参，调用传实参，结果对照验证。

## 返回值函数：把结果“带出来”
### 为什么要学这个知识
先通俗说：打印只是展示，返回值才是“给下游继续用的数据”。
再术语说：`return` 用于结束函数并返回计算结果，是函数组合与数据流传递的关键。

术语卡片：
- 一句话定义：返回值是函数对外输出的数据结果。
- 通俗比喻：快递单号，拿到单号你才能继续追踪。
- 反例：函数里只 `print` 不 `return`，外部拿不到结果再计算。

优点：
- 支持函数组合。
- 支持后续逻辑继续处理。

缺点：
- 新手常把 `print` 当 `return`。

适用场景：
- 计算、转换、校验、数据加工。

不适用场景：
- 只做日志展示且无后续处理。

### return 的使用方式
最小可运行案例：
```python
def add(a, b):
    return a + b

result = add(3, 5)
print("结果是：", result)
print("再乘2：", result * 2)
```

输入示例：
- `3, 5`

输出示例：
```text
结果是： 8
再乘2： 16
```

检查点：
- 外部变量能接住返回值。
- 返回值可以再次参与运算。

先错后对：
- 错误写法：
```python
def add(a, b):
    print(a + b)

x = add(1, 2)
print(x * 2)
```
- 正确写法：使用 `return`。
- 原因：`print` 只显示，函数默认返回 `None`。

边界与限制：
- `return` 后面的代码默认不会执行。

课堂提问（含答案）：
1. 问：`print` 和 `return` 的本质区别？
   答：`print` 面向屏幕，`return` 面向调用方。
2. 问：为什么说返回值是函数组合的基础？
   答：没有返回值就无法把上一步结果交给下一步。

练习题：
- 题目：写函数 `max_of_three(a,b,c)` 返回最大值。
- 解题思路：逐步比较并返回最大。
- 参考答案：
```python
def max_of_three(a, b, c):
    m = a if a > b else b
    return m if m > c else c

print(max_of_three(9, 3, 7))
```

### 风险提醒
- 忘记 `return` 会导致下游 `TypeError`。

### 考试/面试易错点
- “函数一定要有返回值”这句话是错的，返回值可选。

### 本节小结（3行记忆框架）
- 是什么：函数对外输出数据。
- 为什么：实现函数组合与数据传递。
- 怎么用：return 结果，外部接收再使用。

## 真实项目场景：函数拆分成绩分析
### 为什么要学这个知识
先通俗说：真实开发不是一坨代码，而是“拆小函数 + 主流程编排”。
再术语说：模块化拆分通过单一职责函数降低耦合，提高可测试性。

术语卡片：
- 一句话定义：函数拆分是将复杂任务分解为多个可独立验证的子任务。
- 通俗比喻：像工厂流水线，每个工位负责一个动作。
- 反例：所有逻辑塞到一个函数里，改一点牵一大片。

优点：
- 易读、易测、易改。

缺点：
- 初期设计需要额外思考。

适用场景：
- 中大型脚本、业务流程、团队协作。

不适用场景：
- 极小一次性脚本。

### 场景代码（可运行）
最小可运行案例：
```python
def calc_avg(scores):
    return sum(scores) / len(scores)

def calc_level(avg):
    if avg >= 90:
        return "A"
    elif avg >= 80:
        return "B"
    elif avg >= 60:
        return "C"
    return "D"

def report(name, scores):
    avg = calc_avg(scores)
    level = calc_level(avg)
    return f"{name} 平均分 {avg:.1f}，等级 {level}"

print(report("张三", [88, 92, 79]))
```

输入示例：
- 姓名：张三，分数：[88,92,79]

输出示例：
```text
张三 平均分 86.3，等级 B
```

检查点：
- 更换分数列表，等级会自动变化。
- 每个子函数都可以单独测试。

先错后对：
- 错误写法：在一个函数里写读入、计算、评级、输出全部逻辑。
- 正确写法：按职责拆分为 `calc_avg`、`calc_level`、`report`。
- 原因：分层后定位问题更快。

边界与限制：
- 空列表会导致除零错误，需要在实际项目中先校验 `scores` 非空。

课堂提问（含答案）：
1. 问：为什么函数拆分会提升排错效率？
   答：问题能被限定在某个子函数中。
2. 问：什么时候不必强行拆很多函数？
   答：逻辑极短且无复用价值时。

练习题：
- 题目：把“计算总价+打折+输出订单摘要”拆成3个函数。
- 解题思路：先列职责，再定义函数签名。
- 参考答案：
```python
def calc_total(prices):
    return sum(prices)

def apply_discount(total, rate):
    return total * rate

def make_summary(user, final_amount):
    return f"{user} 应付 {final_amount:.2f} 元"

total = calc_total([20, 30, 50])
final_amount = apply_discount(total, 0.9)
print(make_summary("小美", final_amount))
```

### 风险提醒
- “拆函数”不能脱离业务语义，名字必须表达职责。

### 考试/面试易错点
- 只会说“低耦合高内聚”，不会给具体拆分方案。

### 本节小结（3行记忆框架）
- 是什么：复杂逻辑拆分为职责明确的子函数。
- 为什么：提升可测性与可维护性。
- 怎么用：先定职责，再写签名，再组合调用。

## 一页复盘（含答案）
### 10个必会清单（含答案）
1. 函数定义语法？答：`def 函数名(参数):`。
2. 函数调用时机？答：定义后显式调用。
3. 参数的作用？答：接收外部输入，提升复用。
4. 形参与实参区别？答：占位与具体值。
5. `print` 与 `return` 区别？答：显示 vs 返回。
6. 无 `return` 默认返回？答：`None`。
7. 函数拆分原则？答：单一职责。
8. 何时用关键字参数？答：提升可读性、避免顺序错误。
9. 函数命名建议？答：动词+业务含义，如 `calc_total`。
10. 如何验证函数正确？答：构造输入、对照输出、检查边界。

### 5个必会报错（含触发原因与修复要点）
1. `NameError`：调用了未定义函数。修复：先定义后调用，检查拼写。
2. `TypeError`：参数个数不匹配。修复：核对函数签名与调用实参。
3. `TypeError`：`NoneType` 参与运算。修复：确认函数是否返回值。
4. `IndentationError`：函数体缩进错误。修复：统一4空格。
5. `ZeroDivisionError`：平均值计算分母为0。修复：先判断列表非空。

### 3个综合题（含答案）
1. 题目：写函数 `is_even(n)`，返回是否偶数。
   解题思路：用取模表达式返回布尔值。
   参考答案：
```python
def is_even(n):
    return n % 2 == 0

print(is_even(6))
```
2. 题目：写函数 `format_user(name, age)`，返回“姓名-年龄”。
   解题思路：参数化输入，f-string拼接返回。
   参考答案：
```python
def format_user(name, age):
    return f"{name}-{age}"

print(format_user("小王", 20))
```
3. 题目：写函数 `safe_div(a,b)`，除数为0时返回提示字符串。
   解题思路：先做边界判断，再计算。
   参考答案：
```python
def safe_div(a, b):
    if b == 0:
        return "除数不能为0"
    return a / b

print(safe_div(10, 2))
print(safe_div(10, 0))
```
