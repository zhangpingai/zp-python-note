## 核心知识点精讲
### 为什么要学这个知识
先通俗说：核心知识点决定你写代码时“会不会卡壳”。  
再术语说：该模块知识点是语法规则、执行模型与边界条件的集合。

术语卡片：
- 一句话定义：核心知识点是本章必须掌握的最小能力集合。
- 通俗比喻：像做饭前必须先会刀工和火候。
- 反例：只会抄代码，不理解规则，稍改需求就报错。

优点：
- 形成稳定的解决问题路径。

缺点：
- 需要主动归纳，不是看一遍就会。

适用场景：
- 章节练习、面试题、业务小功能开发。

不适用场景：
- 完全无代码实践的被动学习。

先错后对：
- 错误写法：只写功能，不做边界校验。
- 正确写法：先做输入/条件校验，再执行核心逻辑。
- 原因：边界没处理是线上 bug 主要来源。

最小可运行案例：
`python
raw = "18"
if raw.isdigit():
    value = int(raw)
    print("可计算：", value + 2)
else:
    print("输入不合法")
`

输入示例：
- aw = "18"

输出示例：
`	ext
可计算： 20
`

检查点：
- 非数字输入时不会抛异常。

边界与限制：
- 输入不规范时必须先校验，不能直接强转。

课堂提问（含答案）：
1. 问：为什么校验要写在转换前？  
   答：先校验可避免运行时异常中断。
2. 问：边界条件和主流程哪个先写？  
   答：建议先识别边界，再实现主流程。

练习题：
- 改造示例：让它支持负数输入并输出计算结果。

### 风险提醒
- 忽略边界条件会导致“偶发性 bug”。

### 考试/面试易错点
- 说不清“为什么这样写更稳健”。

### 本节小结
- 是什么：核心知识点是本章最小能力闭环。  
- 为什么：决定代码可用性与稳定性。  
- 怎么用：先规则、再实现、最后验证边界。

## 课堂实战与项目化练习
### 为什么要学这个知识
先通俗说：会做题不等于会做项目，必须训练“组合能力”。  
再术语说：实战环节用于验证知识迁移（knowledge transfer）和问题分解能力。

术语卡片：
- 一句话定义：实战是将多个知识点组合为可运行功能的过程。
- 通俗比喻：把零件装成一台可工作的机器。
- 反例：每个知识点都懂，但拼不成完整程序。

优点：
- 提升真实开发信心。
- 能快速暴露并修复薄弱点。

缺点：
- 一开始会觉得难，需要拆步骤。

适用场景：
- 作业、面试手写题、项目初稿。

不适用场景：
- 只想停留在概念层面。

最小可运行案例：
`python
name = input("请输入姓名：")
score = float(input("请输入成绩："))
if score >= 60:
    print(f"{name}：通过")
else:
    print(f"{name}：未通过")
`

输入示例：
- 姓名：小明
- 成绩：78.5

输出示例：
`	ext
小明：通过
`

检查点：
- 输入数值后能正确分支输出。

边界与限制：
- 输入非数字会报错，生产场景应加异常处理。

课堂提问（含答案）：
1. 问：这段代码最先需要补强什么？  
   答：输入异常处理和数据校验。
2. 问：为什么实战要先做最小版本？  
   答：先保证可跑，再迭代功能，风险更低。

练习题：
- 扩展这个程序：增加“优秀/良好/及格/不及格”四档输出。

### 风险提醒
- 一次性写太多功能，排错成本会指数上升。

### 考试/面试易错点
- 不会把需求拆成“输入-处理-输出”三段。

### 本节小结
- 是什么：多知识点组合实战。  
- 为什么：验证真实编码能力。  
- 怎么用：先最小可运行，再逐步增强。

### 5个必会报错（含触发原因与修复要点）
1. SyntaxError：语法结构错误；修复：检查冒号/括号/缩进。
2. IndentationError：缩进层级错误；修复：统一4空格。
3. NameError：变量未定义；修复：先定义再使用。
4. TypeError：类型不匹配；修复：先做类型转换。
5. ValueError：值格式不合法；修复：先校验输入内容。
